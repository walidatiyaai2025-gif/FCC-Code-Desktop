# P08-001 — Owned process-tree supervisor

## Scope

`FCCD-P08-001` establishes the process-lifecycle ownership foundation for P08. It does not implement terminal emulation, streaming logs, profile discovery, or graceful-to-forced cancellation policy.

The contract lives in `FCCCodeDesktop.Runtime` so the lifecycle primitive is independent of the later ConPTY/UI layer. `FCCCodeDesktop.Terminal` remains reserved for terminal-host concerns introduced by later P08 tasks.

## Ownership model

Every process started by `ProcessSupervisor` receives:

- an opaque `OwnershipId` generated by the supervisor;
- the root process ID and start timestamp;
- a private Windows Job Object;
- `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` so owned descendants cannot silently survive supervisor disposal;
- Job Object accounting so the logical completion task waits until the entire owned tree is empty, not merely until the root executable exits.

The API deliberately exposes no arbitrary-PID kill operation. A caller can terminate only through the `ISupervisedProcess` handle returned for a process tree this supervisor started.

## Launch safety

Launch uses `ProcessStartInfo.ArgumentList` with `UseShellExecute=false`; caller arguments are never interpolated into a command shell by the supervisor. Arguments and environment overrides are bounded before launch. Missing executables, access denial, invalid working directories, unsupported platforms, and other launch failures return typed status without registering fake ownership.

If a process starts but cannot be assigned to its Job Object, the start is failed closed and best-effort cleanup is performed before the failure is returned.

## Deliberate P08 task boundary

P08-001 exposes one immediate `TerminateOwnedTreeAsync` primitive because later cancellation/recovery logic needs a trustworthy forced-cleanup endpoint. The following remain explicitly out of scope:

- P08-002: graceful cancellation signal and timeout-based escalation to the forced primitive;
- P08-003: bounded stdout/stderr streaming and backpressure;
- P08-004: ConPTY creation, resize and terminal I/O;
- P08-005/P08-006: shell/profile discovery;
- P08-007: interactive terminal UX;
- P08-008: aggregate phase safety scenarios.

## Cloud validation

Windows CI real-process fixtures prove:

- a launched root is registered while active and removed after natural tree completion;
- root exit alone does not complete the owned handle while a descendant in the Job Object remains alive;
- forced owned-tree termination removes that descendant;
- an independently launched, unowned sentinel process remains alive during owned-tree termination and supervisor disposal;
- supervisor disposal cleans a live owned tree;
- a missing executable returns a typed failure without ownership leakage;
- pre-cancelled launch does not start a process;
- argument safety bounds fail before mutation.

These tests run against real Windows processes and Job Objects in the permanent Windows Release CI. They require no owner-only environment and create no new `FINAL_OWNER_ACCEPTANCE_QUEUE` item.

## Non-claims

This task does not close P08, authorize P09/P13, implement cancellation escalation/log streaming/ConPTY, satisfy either existing P04/P05 owner-last blocker, or imply release readiness / `VERIFIED_FINAL_COMPLETE=true`.
