# FCC Code Desktop — Dependency Policy

## Purpose

This policy is the canonical P01 baseline for reproducible SDK selection, NuGet version ownership, lock-file usage, and intentional dependency updates.

## .NET SDK

- The repository pins .NET SDK `10.0.400` in `global.json`.
- `rollForward` is `disable`.
- prerelease SDK selection is disabled.
- A machine that does not have the exact SDK must fail rather than silently selecting a different SDK.
- SDK changes require an explicit reviewed change to `global.json` plus full restore/build/quality/dependency validation.

## NuGet version ownership

`Directory.Packages.props` is the only repository-level package-version manifest.

- Central Package Management is enabled.
- `CentralPackageVersionOverrideEnabled` is false.
- Every external `PackageReference` must omit `Version` and `VersionOverride`.
- Every referenced external package must have one central `PackageVersion` entry.
- Package versions must be exact; floating versions, ranges, and MSBuild-computed version expressions are rejected by the validator.

The current P01 foundation intentionally has zero external `PackageReference` entries. The central manifest is still committed now so later dependency introduction begins from a deterministic policy rather than creating a second versioning convention.

## Lock files

`Directory.Build.props` enables lock-file generation and defaults restore to locked mode. Every repository project has a committed sibling `packages.lock.json`.

The initial 16 lock files were generated by .NET SDK `10.0.400` from the integrated solution. They use NuGet lock-file schema version 2 and currently record the project-reference dependency graph; they are not hand-authored evidence. Git stores `packages.lock.json` with LF line endings through `.gitattributes`; this normalization changes only repository text representation, not the NuGet-generated dependency content.

Normal restore:

```powershell
dotnet restore .\FCCCodeDesktop.sln --locked-mode --nologo
```

A missing or stale lock file is an error. Do not bypass locked restore to make an unrelated build pass.

## Intentional dependency updates

When adding/removing/upgrading a package:

1. Change `Directory.Packages.props` and project `PackageReference` declarations as one logical change.
2. Regenerate locks explicitly:

   ```powershell
   dotnet restore .\FCCCodeDesktop.sln -p:RestoreLockedMode=false --force-evaluate --nologo
   ```

3. Review every changed `packages.lock.json` for the expected direct/transitive graph.
4. Run a normal locked restore again.
5. Run dependency-policy validation, quality validation, Release build, and the applicable P01 test/CI lane.
6. Commit the central manifest and lock-file changes together.

Do not edit lock-file dependency entries by hand to simulate a restore result.

## Deterministic validation

Run:

```powershell
pwsh -NoProfile -File .\tools\dependencies\validate-dependency-policy.ps1 -RequireDotNet
```

The validator checks:

- exact SDK resolution;
- central package policy and exact-version syntax;
- absence of project-local package versions and overrides;
- lock coverage and lock schema for every project;
- real solution locked restore and Release build;
- missing-lock rejection using a disposable project;
- stale-lock rejection after a central version change;
- explicit lock regeneration and recovery;
- rejection of a project-local package version;
- successful final locked restore/build after recovery.

The package behavior fixture creates versions `1.0.0` and `1.0.1` of a disposable local package in a temporary local NuGet feed. It does not publish packages, mutate owner data, or depend on an external package provider for the fixture lane. Temporary data is removed in a `finally` block.

## Scope boundary

This task does not introduce application dependencies, permanent GitHub Actions CI, test-project infrastructure, build metadata, product runtime functionality, provider calls, Unity execution, or Blender execution. Those remain owned by their respective canonical tasks/phases.
